# Product Requirement Document (PRD) - VendingLink

## 1. Project Overview

**Project Name:** VendingLink (`vending-machine-link-redeem`)  
**Type:** Web Application (B2C & B2B / Vending Machine Digital Redeem System)  
**Target Audience:** General Customers (B2C), Reseller Agents (B2B), and System Administrators.

VendingLink is a web-based platform designed to streamline digital voucher and vending machine stock distribution. 
- **Customers (B2C)** can purchase digital redeem codes directly via QRIS (Midtrans) without needing an account.
- **Agents/Resellers (B2B)** can register, get approved by admins, and purchase products on credit (bypassing payment gateways) to resell, settling their debts later.
- **Administrators** manage products, bulk-upload redeem URL stocks via CSV, approve new agents, track agent debts, and mark payments as settled. 

Additionally, an AI Sales Assistant is available to help answer product and operational questions.

## 3. User Roles & Authentication

### 3.1 Customer (Public / B2C)
- **No Login Required.**
- Can browse the public product catalog.
- Must provide Name and Phone Number (Optional) during checkout.
- Pays via Midtrans Payment Gateway.

### 3.2 Agent (Reseller / B2B)
- **Registration Required:** Dedicated registration page with CTA "Daftar menjadi agen reseller disini".
- **Admin Approval:** Newly registered agents cannot transact until approved by an Admin.
- Access to Agent Dashboard showing sales data and outstanding debt.
- **Checkout:** Bypasses Midtrans. Receives redeem links instantly; transactions are recorded as debt.

### 3.3 Admin (`ROLE = 'ADMIN'`)
- Full access to back-office dashboard (`/admin`).
- Manages products (including uploading usage guide images).
- Bulk uploads stock inventory (Redeem URLs) via CSV.
- Approves/rejects new agent registrations.
- Monitors agent debts and manually marks them as "Lunas" (Paid) upon receiving direct bank transfers.

## 4. Core Features & Functional Requirements

### 4.1 Customer Flow (Public B2C)
1. **Catalog & Checkout:** Customer selects a product, inputs Name and Phone Number.
2. **Payment:** Redirected to Midtrans for QRIS/Snap payment.
3. **Fulfillment:** Upon successful payment, customer is redirected to a success page displaying:
   - The Redeem URL (with a copy button).
   - An instructional guide image on how to use the link.

### 4.2 Agent Portal (`/agent`)
1. **Dashboard & Sales Data:** Displays total sales generated by the agent and total outstanding debt (`uang yang harus disetor`).
2. **Product Catalog:** Grid view of active products with stock availability.
3. **Agent Checkout (Credit Flow):** Agent selects a product and initiates an order. The system bypasses Midtrans, instantly provides the Redeem URL (copyable) + guide image, and adds the product price to the agent's outstanding debt.

### 4.3 Admin Portal (`/admin`)
1. **Agent Management (`/admin/agents`)**:
   - View list of all agents.
   - Approve/reject new agent registrations (`isApproved`).
   - View outstanding debt per agent.
   - **Manual Settlement:** Button to mark an agent's debt as "Lunas". This resets/deducts their outstanding debt after admin verifies manual bank transfer.
2. **Inventory Management (`/admin/inventory`)**:
   - Create/edit products.
   - **Upload Guide Image:** Add an image URL/file that shows how to use the product's redeem link.
   - Bulk upload redeem links/URLs via CSV file.
3. **Dashboard & Reports (`/admin/reports`)**:
   - View total revenue, total agent debt, and transaction logs.

## 5. Database Schema (Prisma)

```prisma
model User {
  id              String   @id @default(cuid())
  username        String   @unique
  passwordHash    String
  role            String   @default("AGENT") // 'ADMIN' | 'AGENT'
  isApproved      Boolean  @default(false)   // Requires admin approval
  isActive        Boolean  @default(true)
  outstandingDebt Int      @default(0)       // Debt to be paid to admin
  createdAt       DateTime @default(now())

  transactions  Transaction[]
  claimedStocks RedeemStock[]

  @@map("users")
}

model Product {
  id            String   @id @default(cuid())
  name          String
  price         Int
  description   String?
  guideImageUrl String?  // Image guide on how to use the redeem link
  isActive      Boolean  @default(true)
  updatedAt     DateTime @updatedAt

  stocks       RedeemStock[]
  transactions Transaction[]

  @@map("products")
}

model RedeemStock {
  id               String    @id @default(cuid())
  productId        String
  redeemUrl        String
  status           String    @default("AVAILABLE") // 'AVAILABLE' | 'SOLD'
  claimedByAgentId String?
  customerName     String?
  customerPhone    String?
  claimedAt        DateTime?
  createdAt        DateTime  @default(now())

  product        Product @relation(fields: [productId], references: [id])
  claimedByAgent User?   @relation(fields: [claimedByAgentId], references: [id])

  @@map("redeem_stocks")
}

model Voucher {
  id             String    @id @default(cuid())
  code           String    @unique
  discountAmount Int
  quota          Int
  usedCount      Int       @default(0)
  isActive       Boolean   @default(true)
  expiresAt      DateTime?
  createdAt      DateTime  @default(now())

  transactions Transaction[]

  @@map("vouchers")
}

model Transaction {
  id             String    @id @default(cuid())
  orderId        String    @unique
  productId      String
  agentId        String?   // Nullable for direct customer purchases
  voucherId      String?
  customerName   String
  customerPhone  String?
  paymentType    String    @default("MIDTRANS") // 'MIDTRANS' | 'AGENT_CREDIT'
  originalPrice  Int
  discountAmount Int       @default(0)
  finalAmount    Int
  status         String    @default("PENDING") // 'PENDING' | 'PAID' | 'EXPIRED'
  isSettled      Boolean   @default(false)     // For agent debt tracking
  redeemUrl      String?
  createdAt      DateTime  @default(now())
  paidAt         DateTime?

  product Product  @relation(fields: [productId], references: [id])
  agent   User?    @relation(fields: [agentId], references: [id])
  voucher Voucher? @relation(fields: [voucherId], references: [id])

  @@map("transactions")
}
```

## 6. API Endpoints Specification

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/api/auth/[...nextauth]` | Public | NextAuth authentication handler |
| `POST` | `/api/auth/register` | Public | Agent registration (sets `isApproved = false`) |
| `GET/PUT` | `/api/admin/agents` | Admin | Manage agents (Approve & Settle Debt) |
| `GET/POST` | `/api/admin/inventory` | Admin | Manage products & bulk upload stock links |
| `POST` | `/api/checkout/customer`| Public | Customer checkout via Midtrans |
| `POST` | `/api/checkout/agent`   | Agent | Agent checkout bypassing Midtrans (adds debt) |
| `POST` | `/api/midtrans` | Webhook | Process Midtrans payment notifications for customers |
| `POST` | `/api/chat` | Agent | Interface with AI Sales Assistant |

## 7. Security & Non-Functional Requirements

- **Authentication & Authorization:** Secure session handling via NextAuth JWT/Prisma tokens with role-based route protection via Next.js Middleware (`middleware.ts`). Unapproved agents are blocked from transacting.
- **Data Integrity:** Database transactions ensure stock link double-claiming is prevented during concurrent orders.
- **Payment Verification:** Webhook signatures verified against Midtrans Server Key to prevent tampering.
- **Responsiveness:** Mobile-first layout for agent portal for easy use on smartphones/tablets in field environments.
